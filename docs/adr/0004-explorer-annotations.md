# ADR 0004 — Stored explorer, versioned location notes and frozen selections

Status: implemented for M3 draft; native concurrency and deployment gates remain open.

## Query saved evidence

Explorer/search/history endpoints depend on `InventoryStore`, not the filesystem adapter. The new `observation_facts` / `observation_search` views combine immutable observations with current evidence pointers, location notes and explicit stale/error flags. `current_group_state` checks current analysis membership as a relation so an invalid member marks its captured group stale. No query opens a source or computes a checksum. The Angular explorer displays source status as cached last validation, along with captured scan/root coverage.

Filters are whitelisted and parameters are bound. Literal byte `position` and byte equality preserve `%`, `_`, case and raw Linux identity. Base64 exact filters address non-UTF-8 names without reconstructing native paths from display text. Mtime predicates and ordering use epoch seconds times 1,000,000,000 plus nanoseconds as PostgreSQL NUMERIC. Byte inputs/results stay decimal strings and Angular uses BigInt for binary units. Server UUID ties and nulls-last ordering make equal-key pages deterministic in both directions.

Search transactions acquire the annotation clock in SHARE mode, then the scan in SHARE mode. Captured contexts bind normalized filters/sort, sequence cutoff, evidence/query/annotation revisions and current analysis ID. A trigger also advances a global search clock on scan query/evidence/analysis updates, covering notes whose baseline belongs to an older scan. Queries read this clock without row locks and recheck it after the result query; a change rejects the response instead of mixing revisions. Workers lock scan then search clock; queries never lock that global clock, avoiding a scan/clock lock inversion. The cursor carries an anchor UUID; its immutable sort value is resolved in PostgreSQL, keeping cursor size bounded even for long paths. A changed context rejects continuation. New committed observations are excluded by cutoff; updates to existing query inputs advance revisions. This is conservative: unrelated annotation or scan-evidence/status edits can require refresh. Workers do not lock the annotation clock. Job creation retains admission-first locking; frozen hash requests then take annotation SHARE and scan UPDATE locks. No explorer operation takes scheduler/job/work locks, avoiding an inversion with worker fencing.

Pages default to 100 and cap at 500. Indexed source/location parents and recursive SQL resolve subtree scope; the application never loads an entire source tree. The UI holds at most 1,000 visible directory nodes and reports its bound, while breadcrumbs cap at 256. Existing scan-entry size/time/page indexes, location-parent indexes, and V4 annotation/tag/pending/history/hash indexes support typed predicates. Literal substring queries still require scanning candidate metadata; no million-row performance claim is made.

## Location annotations and audit

`file_annotation` maps the specification's manual location memo/review record; `file_annotation_tag` maps its `file_tag`. Empty notes are a virtual version 0. Writes serialize through the singleton annotation clock and compare an expected location version before replacing the memo, review state and bounded tag set. Both first-insert races and stale overwrites are rejected; every change commits with its audit event. No native file lock or source mutation is involved.

A note captures the observation and accepted attempt against which it was affirmed. Observed fingerprint/digest changes or invalidated evidence preserve the note and expose `needsReview`. Saving explicitly reaffirms that baseline. Rescans reuse only identical raw path/source-instance locations; renamed locations inherit nothing. Bulk tag/review edits preserve an existing memo's baseline. Derived signature findings remain a separate future M4 concern.

Tag labels preserve display spelling and compare by Unicode NFKC followed by Locale.ROOT lowercase. This policy is intentionally limited to tags. Labels are trimmed 1–64 code points, memos at most 20,000, and associations at most 100 per location. NUL and invalid surrogate sequences are rejected. Shared tag renames compare a separate tag version. Angular interpolates text; no `innerHTML` or source-serving endpoint is introduced.

## Frozen bounded selections

`selection` captures actor, scan, analysis/evidence/query/annotation context, query, cutoff, count, known bytes, unknown-size count and 24-hour expiry. `selection_member` has immutable entry/location IDs, a deterministic ordinal, annotation version/full snapshot, accepted attempt and stale state. Composite foreign keys bind observations and attempts to their scan. Selection creation resolves all matches inside the captured query transaction; more than 500 fails without truncation. This is the groundwork for AT-52, not an implemented review plan or export.

Preview exposes captured annotations alongside current member state. Batch writes lock the annotation clock and scan, validate every member version/tag snapshot/evidence pointer and current analysis, then update at most 500 rows atomically with item and summary audit events. A conflict applies zero changes. A successful selection applies once; identical idempotency-key retries return the saved response before expiry/version checks. New inventory rows never join a captured set and do not by themselves block a batch. The same actor-bound selection can explicitly schedule eligible regular-file checksums; it cannot bypass frozen-inventory or evidence validity checks.

Selections, full audit snapshots and prior analyses are retained. There is no automatic purge yet. Operators must monitor database growth and back up application metadata. The single clock favors simple verifiable concurrency over parallel metadata writes; independent native-session contention and scale remain measured acceptance work.
